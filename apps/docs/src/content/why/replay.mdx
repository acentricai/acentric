**The claim:** a session is its first state plus the messages it received,
with the time of each. Delivering the same messages again gives the same states
and the same log, every time, with no model, network or handler running.

That makes a session reproducible. A bug seen in production replays on your
laptop, step by step. New code can be replayed over old sessions, to see what
it would have done differently before it is deployed.

## In a loop

A loop's run depends on everything it awaited: each model reply, each tool
result, and when each input arrived. Reproducing one means recording all of
that, usually by intercepting its network calls, then running the loop again
against the recording, with the same timing. If the code has changed, the new
loop may make different calls, and the recording no longer fits.

## As a reducer

Everything an agent learns from the world reaches `step` as a message. A
model's reply is an `effect` message; so is a tool's result and a timer firing.
So the messages a session received are the whole of its input, and `step` is a
pure function of them. Replaying is delivering them again, in order, each at
its time. No handler runs, so nothing is sent twice: the model's replies are in
the messages.

This agent lets a user send at most 3 messages a minute. It has a bug: it
checks with `>` where it should use `>=`, so a fourth message gets through.

```ts title="src/agent.ts"
import type { Agent } from '@acentric/types';

type Snapshot = { recent: number[] };

const agent: Agent<Snapshot> = {
  name: 'limiter',
  version: '0.1.0',

  init: () => ({ snapshot: { recent: [] } }),

  step: ({ snapshot }, message, now) => {
    if (message.type !== 'input') return { snapshot };
    const recent = snapshot.recent.filter((at) => now - at < 60_000);
    if (recent.length > 3)
      return { snapshot, append: [{ kind: 'limited', body: null }] };
    return {
      snapshot: { recent: [...recent, now] },
      append: [{ kind: 'accepted', body: message.payload }],
    };
  },
};

export default agent;
```

The fix changes one comparison:

```ts title="src/fixed.ts"
import type { Agent } from '@acentric/types';

import agent from './agent.js';

type Snapshot = { recent: number[] };

const fixed: Agent<Snapshot> = {
  ...agent,
  version: '0.1.1',
  step: ({ snapshot }, message, now) => {
    if (message.type !== 'input') return { snapshot };
    const recent = snapshot.recent.filter((at) => now - at < 60_000);
    if (recent.length >= 3)
      return { snapshot, append: [{ kind: 'limited', body: null }] };
    return {
      snapshot: { recent: [...recent, now] },
      append: [{ kind: 'accepted', body: message.payload }],
    };
  },
};

export default fixed;
```

A replay is a loop over recorded messages. This one uses `simulate` from
`@acentric/testing`, which runs the steps as a runner would:

```ts title="replay.ts" run
import assert from 'node:assert/strict';

import { simulate } from '@acentric/testing';
import type { Agent, JsonObject, Message } from '@acentric/types';

import agent from './src/agent.js';
import fixed from './src/fixed.js';

type Recorded = { at: number; message: Message };

/** Delivers each recorded message at its time, and returns the log. */
function replay<S extends JsonObject>(code: Agent<S>, recorded: Recorded[]) {
  const session = simulate(code, {});
  for (const { at, message } of recorded) {
    session.advance(at - session.now);
    session.send(message);
  }
  return session.log.map(({ seq, at, kind }) => ({ seq, at, kind }));
}

// What a session received: five messages, four of them in its first minute.
const recorded: Recorded[] = [0, 10_000, 20_000, 30_000, 70_000].map((at, i) => ({
  at,
  message: { type: 'input', id: `m${i + 1}`, kind: 'say', payload: { n: i + 1 } },
}));

// The same messages give the same log, every time.
const first = replay(agent, recorded);
assert.deepEqual(replay(agent, recorded), first);
assert.deepEqual(
  first.map((entry) => entry.kind),
  ['accepted', 'accepted', 'accepted', 'accepted', 'accepted'],
);

// Replayed on the fix, the same session differs at the fourth message.
const after = replay(fixed, recorded);
const differs = first.findIndex((entry, i) => entry.kind !== after[i]?.kind);
assert.equal(differs, 3);
assert.deepEqual(after[3], { seq: 4, at: 30_000, kind: 'limited' });
```

## What is missing

Runners keep a session's latest snapshot, its log and its effects. They do not
keep the messages it received: the log holds only what the agent chose to
append. So the example above records its messages by hand.

The change is for a runner to record each delivered message with its `now`, in
the same save as the step it led to. That costs one more record per step. With
it, an `acentric replay` command can re-run a stored session on the code you
have, and report the first step that differs. This page will show that when it
exists.

## The proof

- **The example above runs in our docs check.** It shows replay is
  deterministic, and that replaying new code finds where it differs.
- **The replay of a live session is not proven yet,** because no runner records
  the messages. The claim on the overview is marked as coming until it does.
